# 项目启动与访问

更新时间：2026-08-09

## 一键启动和停止

在 GPU 节点进入项目目录后执行：

```bash
cd /share/home/lifr/workspace/code/job-match-tune
bash scripts/serve/start_project.sh
```

脚本会：

- 使用当前已激活的 `tune-demo` 环境；未激活时通过 `conda run` 使用该环境；
- 后台启动 API 和前端；
- 固定使用 API `8000`、前端 `5174`；
- 检查端口占用和服务健康状态；
- 将日志写入 `outputs/logs/`，将 PID 写入 `outputs/runtime/`。

默认使用更省显存、便于调试的 Transformers 4-bit 后端。需要并发或批量吞吐时，可以让统一脚本同时管理 vLLM、API 和前端：

```bash
JOBMATCH_INFERENCE_BACKEND=vllm \
bash scripts/serve/start_project.sh
```

此模式会先启动 vLLM 并等待 `/v1/models` 就绪，再启动 API 和前端；停止脚本会依次清理 API、前端和 vLLM 进程。额外日志位于 `outputs/logs/vllm.log`。运行环境必须已安装 `vllm` 和 `openai`；缺少依赖时脚本会在启动任何进程前退出。

安装前先按 vLLM 官方文档核对 CUDA、PyTorch 与 vLLM 版本兼容性；确认后在项目环境安装：

```bash
conda activate tune-demo
pip install vllm openai
```

vLLM 下，单次匹配会并行提交 JD/简历解析，批量接口也会受控并发。默认最多同时向 vLLM 提交 4 个请求，可按显存和延迟压测结果调整：

```bash
JOBMATCH_INFERENCE_BACKEND=vllm \
JOBMATCH_VLLM_MAX_CONCURRENCY=2 \
bash scripts/serve/start_project.sh
```

设为 `1` 会退回串行。也可以用 `JOBMATCH_PARALLEL_MATCH_PARSE=0` 单独关闭一次匹配内的 JD/简历并行。

停止两个服务：

```bash
bash scripts/serve/stop_project.sh
```

查看日志：

```bash
tail -f outputs/logs/api.log
tail -f outputs/logs/frontend.log
tail -f outputs/logs/vllm.log
```

可以通过环境变量覆盖默认值：

```bash
CUDA_VISIBLE_DEVICES=1 \
JOBMATCH_API_PORT=8000 \
JOBMATCH_FRONTEND_PORT=5174 \
bash scripts/serve/start_project.sh
```

Transformers 模式下，14B 模型会在首次发起任务时自动加载；页面会把首次加载和匹配合并成一个按钮，并提示预计等待时间。vLLM 模式会在启动脚本返回前完成模型加载。

## 推理性能对比

统一使用同一批人工留出样本比较后端，不要用单个示例判断：

```bash
conda run -n tune-demo python scripts/eval/benchmark_match_api.py \
  --samples 4 \
  --concurrency 2 \
  --max-new-tokens 512 \
  --out outputs/eval_reports/match_api_benchmark.json
```

报告只保存样本 ID、成功状态、后端、解析模式和延迟，不复制 JD/简历正文。重点比较成功率、p50/p95、吞吐和产品 holdout 指标；只有速度和质量同时通过才切换默认后端。

## 登录节点到 GPU 节点的端口转发

已有命令：

```bash
ssh -R 7897:127.0.0.1:7897 gpu03
```

其中 `-R 7897` 是让 GPU 节点通过登录节点的 `7897` 使用代理，并没有把 GPU 节点的项目端口转发给浏览器。

从登录节点进入 `gpu03` 时，应增加两个本地转发：

```bash
ssh \
  -R 7897:127.0.0.1:7897 \
  -L 5174:127.0.0.1:5174 \
  -L 8000:127.0.0.1:8000 \
  gpu03
```

这一步会把登录节点的 `5174/8000` 接到 GPU 节点。要让个人电脑浏览器访问，还需要在“个人电脑 → 登录节点”的第一层 SSH 中转发同样两个端口：

```bash
ssh \
  -L 5174:127.0.0.1:5174 \
  -L 8000:127.0.0.1:8000 \
  用户名@登录节点地址
```

连接顺序如下：

```text
个人电脑 localhost:5174/8000
        ↓ 第一层 -L
登录节点 127.0.0.1:5174/8000
        ↓ 第二层 -L
gpu03 127.0.0.1:5174/8000
```

保持两层 SSH 会话均处于连接状态，然后在个人电脑浏览器打开：

```text
http://localhost:5174
```

如果使用 VS Code Remote-SSH 直接连接 `gpu03`，也可以在“端口”面板分别转发 `5174` 和 `8000`。

## 常见问题

### 端口已被占用

先尝试停止当前项目：

```bash
bash scripts/serve/stop_project.sh
```

如果仍提示占用，用下面的命令确认占用者，不要直接批量杀进程：

```bash
ss -ltnp | grep -E ':(5174|8000)\b'
```

### 页面打开但显示未连接

确认 API 隧道和健康检查：

```bash
curl http://127.0.0.1:8000/health
```

浏览器页面和 API 必须同时转发，仅转发 `5174` 无法完成人岗匹配。

### 页面可以打开但 Vue 没有加载

前端使用 `frontend/package-lock.json` 锁定 Vue/Vite，并在 GPU 节点本地构建静态资源。首次运行需在项目目录执行 `npm ci --prefix frontend`，之后浏览器不依赖外部 CDN。
