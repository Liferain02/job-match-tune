# 项目结构说明

更新时间：2026-08-09

仓库按“数据与训练实验 + 推理应用”组织。两条链路共用 schema、prompt、后处理和评测口径，但运行资产与源码必须分离。

## 顶层目录

| 路径 | 职责 | 是否进 Git |
| --- | --- | --- |
| `src/jobmatch_tune/` | Python 包与所有核心逻辑 | 是 |
| `configs/` | 标签、数据源、配比和当前 14B 训练配置 | 是 |
| `scripts/` | 数据、训练、评测、服务和开发入口 | 是 |
| `frontend/` | Vue 3 ESM 静态工作台 | 是 |
| `tests/` | Python 单元/回归测试与前端 smoke | 是 |
| `data/eval/` | 人工 gold、人工 seed、小型 review seed | 是 |
| `data/raw/`、`data/interim/`、`data/sft*` | 可重建数据资产 | 否 |
| `models/` | 本地基座模型 | 否 |
| `outputs/` | adapter、日志、manifest 和评测报告 | 否 |
| `docs/history/` | 已结束的历史实验记录 | 是 |

`data/eval/` 中名字包含 `*_train_pool_*` 的文件也是 builder 产物，不再跟踪。人工训练 seed 可以保留，但必须能说明来源、授权、脱敏状态和用途。

## Python 包

```text
src/jobmatch_tune/
├── api/          FastAPI 路由、推理后端和上传 helper
├── crawler/      官网抓取、公开导出导入和探测代码
├── dataset/      SFT、preference、candidate/train pool builder
├── eval/         gold 构造、指标、readiness、回归比较
├── inference/    prompt、模型加载、JSON 修复和 schema
├── match/        可解释规则匹配基线
├── preprocess/   JD 清洗、去重、字段规则和 taxonomy
├── resume/       文件抽取、OCR sidecar、归一化和隐私处理
├── train/        QLoRA、DPO 和 run manifest
└── utils/        JSONL IO、模型下载等小型公共工具
```

依赖方向原则：

```text
api → inference / match / resume
train → dataset / manifest
dataset → preprocess / resume / utils
eval → inference / match / dataset / utils
```

目前 `api/server.py` 同时承担配置、后端生命周期、文件解析和路由。虽然文件较大，但核心流程仍清晰，暂不为了分层而拆分；只有新增功能明显影响测试和维护时再处理。

## 脚本

- `scripts/data/`：下载/抓取、建池、审计和 readiness。
- `scripts/train/`：当前 Qwen3-14B SFT / DPO 与 smoke。
- `scripts/eval/`：adapter 三任务评测、产品门禁和回归比较。
- `scripts/serve/`：Transformers API、vLLM 与静态前端。
- `scripts/dev/`：依赖安装和模型下载。

历史 1.7B shell 入口已删除；实验结论仍保留在 `docs/history/` 和 Git 历史中。短 shell wrapper 虽然偏多，但当前只删除无人使用的文件，不再额外设计统一 CLI。

## 推荐入口

```bash
# 数据
bash scripts/data/build_current_data_pools.sh
bash scripts/data/report_training_readiness.sh

# 训练
bash scripts/train/train_qwen3_14b_smoke.sh
bash scripts/train/train_qwen3_14b_multitask_sft.sh

# 产品评测
bash scripts/eval/run_product_adapter_suite.sh

# 应用
bash scripts/serve/start_api.sh
bash scripts/serve/start_frontend.sh
```

所有当前脚本从自身位置解析仓库根目录，不再依赖某个用户的绝对 home、conda 安装目录或 workspace 路径。调用者负责先激活正确环境。
