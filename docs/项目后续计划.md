# 项目后续计划

更新时间：2026-08-13

当前项目不再保留一串已经完成或缺少数据依据的功能 TODO。产品继续聚焦 JD 解析、简历解析和可解释人岗匹配；完整当前状态见[秋招项目总结](秋招项目总结/README.md)。

## 唯一外部解锁条件

获得新的、合法、独立、去标识化的 Resume 和 Match 数据，并使对应 readiness 通过：

- Resume 必须增加真正独立的来源实体，不能用模板、OCR 或改写变体扩量。
- Match 必须增加真实观察或独立人工判断的 Pair，不能继续全部由现有规则合成。
- 显式年限条件必须同时覆盖满足与不满足样本。
- 许可、来源、隐私、内容去重、实体切分和 Gold 泄漏审计全部通过。

在这个条件满足前，不运行新 Resume/Match/Multitask SFT，不恢复 DPO，也不通过下调门槛让报告变绿。

## 新数据出现后的长期循环

1. 记录来源、版本、许可、用途和采集时间。
2. 独立执行隐私清洗、内容去重和来源组归并。
3. 按实体先切分、后配对，复核关键条件正负分布。
4. 生成 readiness 和 freshness 报告；门禁未过则停止。
5. 门禁通过后才训练，并保存 run manifest。
6. 对冻结 Gold V1 做只读回归，同时建立新的独立扩展 Gold。
7. 只有业务指标有可复现提升才晋级 adapter；否则保留实验记录并回到数据审查。

这个循环可长期运行。“没有新证据，继续保持停止”是合法结果，不需要用新模块或更多合成数据制造进度。

## 保持冻结的事项

- 不针对 25 条 Gold V1 的三个已知错例编写专用规则，不重算或覆盖其历史冻结哈希。
- 不扩成 ATS，不做职位发布、候选人管道、多租户、权限、简历编辑器或面试题等外围功能。
- 不在现有规模引入微服务、任务队列、插件平台或新的模型层。
- 不把 vLLM、DPO、embedding 或 reranker 当作默认下一步；只有数据与实测证据支持时再启用。
- 只修复影响核心流程、安全或评测可信度的确定性问题。

## 当前可持续维护动作

没有新数据时，只做只读审计、依赖/安全更新、核心回归和中文文档校正。已知限制集中记录在[发现但未处理的技术债](秋招项目总结/发现但未处理的技术债.md)，不把每一项限制自动升级为开发任务。
