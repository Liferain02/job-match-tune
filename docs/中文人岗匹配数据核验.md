# 中文人岗匹配数据核验

更新时间：2026-08-09

## 结论

当前没有发现一个同时满足“中文真实人岗行为、公开下载、明确允许本项目训练与再分发、来源可追溯”的数据集。因此，本轮不把新的外部匹配数据混入 SFT/DPO 主集。

这不是数据搜寻失败，而是明确的数据治理结果：宁可继续使用规模较小但可解释的人工/可控配对，也不把竞赛受限数据、来源不明简历或 LLM 合成标签包装成 gold。

本轮已经落地三项改动：

1. 外部匹配行必须同时满足许可证已确认、训练用途获准、来源可追溯，才能进入组合训练池。
2. `med2425/resume-job-fit-merged-v1` 的 JD 字段从错误的 `job_description` 修正为上游真实字段 `jd`。
3. 天池 2019 数据被记录为需授权候选源，不提供自动下载，也不接受非官方镜像。

## 核验结果

### 天池 2019 智联招聘人岗智能匹配

官方竞赛编号是 `231728`。官方说明显示，数据来自智联招聘抽样并脱敏，包含简历表、职位表和行为表；行为信号依次包括浏览、主动投递和 HR 认可。它比简单的“简历/JD 是否匹配”分类更接近真实双边推荐流程。

但官方页面只说明报名后可下载，没有给出开放数据许可证。通用天池参赛协议还把平台或举办方提供的材料纳入受约束信息，具体权利以报名时协议为准。故本项目不能从第三方镜像获取、提交仓库或默认用于产品训练。若以后取得授权，需要同时保存：

- 报名时实际签署的协议与日期；
- 允许的用途（研究、内部训练、商业使用、模型分发分别确认）；
- 官方下载文件 hash；
- 脱敏和敏感属性处理记录。

### ConFit 系列如何处理这类数据

ConFit 将匹配建模为检索问题，使用对比学习和 batch 内负例缓解交互稀疏；ConFit v2 增加假想简历扩写与 runner-up hard negative mining；ConFit v3 则在检索 top-20 后，用 4 个候选组成 listwise 重排窗口。

对当前项目最值得吸收的不是再叠一个复杂模型，而是以下数据原则：

- 按 job/resume 实体分组切分，禁止同一实体跨训练与评测集；
- 不把所有未观测配对直接当强负例，优先使用曝光后未投递/未认可和检索近邻作为难负例；
- 先过滤没有正例、负例不足、正例异常多的候选组；
- 质量优先于数量。ConFit v3 的消融显示，清除疑似噪声样本的收益高于保留更多 RL 数据；
- 姓名、联系方式、性别、年龄、民族等敏感信息在训练前删除，并单独做公平性评测。

当前项目暂不直接照搬 listwise RL。现阶段数据规模和人工 gold 还不足，先把分组切分、标签来源和难负例审计做扎实，收益更确定、复杂度更低。

### 两个 Hugging Face 匹配集

`med2425/resume-job-fit-merged-v1` 共 93,733 条，数据卡说明其合并其他数据、生成跨域配对，并使用 Qwen2.5-32B 标注。它适合用于研究合成标签分布和英文格式覆盖，不是人工 gold；同时没有声明许可证。

`cnamuangtoun/resume-job-description-fit` 没有数据卡、许可证和原始来源说明。即使文件可直接下载，也不满足训练门禁。

两者在 `configs/public_match_sources.yaml` 中均标记为 `audit_only`。导入后可以生成质量报告，但不会进入组合训练池。

## 后续获得授权数据时的最小处理流程

```text
官方文件 + 协议快照 + hash
          ↓
字段映射与敏感信息删除
          ↓
按 user_id / jd_no 分组去重与切分
          ↓
构造显式正例、曝光负例、近邻难负例
          ↓
检查正负比例、实体泄漏、模板重复和标签冲突
          ↓
先进入独立离线评测，再决定是否进入训练
```

停止条件不是“文件下载成功”，而是许可、隐私、来源、切分和标签质量全部通过。
