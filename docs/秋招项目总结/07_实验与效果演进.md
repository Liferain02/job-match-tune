# 实验与效果演进

## 阶段 1：原型闭环（2026-05-15）

初版完成 JD 抓取、清洗、SFT/QLoRA、推理、JSON 后处理、API、静态页面和基础评测。模型配置从 1.7B/4B 方案起步，目标是尽快验证“文本到结构化字段”能否闭环。

这一阶段的价值是证明技术路径，限制是任务以 JD 为主，数据与评测证据还不够严格。

## 阶段 2：14B、Resume 与 Match（2026-05-16 至 05-18）

主模型转向 Qwen3-14B，加入 DPO 支持、简历文件/OCR/结构化解析、确定性匹配规则、Match API 和多任务训练数据。前端从单体脚本重构为 Vue 3 组件。

产品从单一解析器变成 JD—Resume—Match 主流程，但同时引入了 Pair 合成、实体复用和简历隐私等更难的数据问题。

## 阶段 3：质量数据、readiness 与多任务（2026-05-31）

加入 JD 质量集、来源审计、严格/可修复数据分层、多任务 registry 和 freshness。思路从“能训练”转向“满足什么条件才允许训练”。

## 阶段 4：SFT、DPO 与实验门禁（2026-06-01 至 06-02）

历史正式 SFT 比较了 DFT 与 NLL：均使用 9,800 条 train、320 条 eval、1 epoch、613 optimizer steps，耗时约 8,050 秒与 8,029 秒。两种 loss 定义不同，loss 数值本身不可直接比较。

旧 JD 50 条评测两条路线结果接近；Resume SFT 的多字段指标较高，归一化重放后 strength F1 达 0.99375。历史 DPO 使用 4,400 条对话偏好、1 epoch、275 steps，训练末 loss 0.2099、eval loss 0.1749、reward accuracy 0.9297、margin 3.3643，但没有证明独立业务收益。

这些数字是历史实验记录，不等于当前独立产品结论。尤其旧 64 条 Match 结果因训练污染已失效。

## 阶段 5：代码和产品收敛（2026-08-10）

删除旧 1.7B 主路径和大量过时英文文档/legacy 脚本，简化 README；随后恢复中文操作文档，加入统一启停脚本、分组切分、管线 freshness 和数据审计工具。推理层明确 Transformers 与 vLLM 两种运行模式，vLLM 支持 JD/Resume 受控并发。

## 阶段 6：Gold 与数据证据校正（2026-08-12 至 08-13）

审计发现旧 Match holdout 并不独立，于是建立 25 条候选、完成人工复核、检查五类训练重叠并冻结 Gold V1。Product Final 达到：

- 命中技能 F1 0.990649；缺失技能 F1 0.986667。
- 匹配等级和方向 EM 均为 0.96。
- 学历、年限和解释一致率均为 1.0。

同时修正来源组：Resume SFT 15,470 行、有效来源组 2,557、bootstrap 占 98.75%；Match 4,798 Pair 全合成；年限显式样本 1,944 条全为不满足。最终 Resume/Match/Multitask readiness 都为 `false`。

## 如何理解效果提升

Gold 上 Raw 到 Product Final 的大幅提升不是单一模型版本带来的 A/B 结论。它综合了字段修复、证据约束、方向/技能归一化和固定规则。因此可对外表述为“构建了分层、可审计流水线并达到最终指标”，不能表述为“微调将准确率从 0.56 提升到 0.96”。

## 当前最成熟的结论

1. 混合系统比直接生成一个 Match 结论更稳定、可解释。
2. QLoRA 能以较低显存成本建立结构化任务能力。
3. DPO 的偏好指标不自动转化为业务提升。
4. 数据来源、实体切分和真实 Pair 证据比继续调超参数更关键。
5. 当前最合理的实验状态是冻结基线并等待满足准入的新数据。

## 下一次实验的启动模板

只有 readiness 改变后才开新实验，并预先记录：新数据的许可/隐私/独立实体增量、条件分布增量、训练配置与 run manifest、Gold V1 不退化指标、新扩展 Gold 的主指标以及失败回滚条件。没有这些内容，就不把训练称为正式实验。
