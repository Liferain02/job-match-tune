# 评测体系与可信度治理

## 为什么分三层评测

系统质量来自模型、后处理和规则共同作用，因此只报最终分数会掩盖问题来源。当前评测分为：

- Raw：原始 JD/Resume 模型解析结果进入同一固定 scorer；不是模型直接预测 Match。
- Normalized：经过通用 JSON 修复、字段归一化和证据约束后再评分。
- Product Final：最终结构化规则结果与解释输出。

这种分层能回答“模型抽取差”“归一化差”还是“规则差”，也避免把工程修复的收益包装成模型训练收益。

## 正式 Match Gold V1

Gold V1 共 25 条，25 条全部人工复核，`gold_ready=true`。它覆盖 AI/后端交叉、单项硬门槛、可迁移技能、项目技能证据、技能同义词、OCR 噪声、相近岗位方向、学历不完全满足、年限不足但项目强等 9 类难例。

五类重叠审计全部为 0：完整 Pair、Match JD、Match Resume、JD 单任务、Resume 单任务。冻结信息见[人岗匹配黄金集第一版冻结基线](../人岗匹配黄金集第一版冻结基线.md)。

## “人工 holdout”是什么意思

Holdout 是在训练和调参期间完全隔离、最后才用于检验泛化的留出集。“人工 holdout”还意味着标签由人审核，而不是由生成规则或同一个模型自产。它至少需要：样本未进入训练、没有实体/模板泄漏、标签有审核记录、评测前冻结。

本项目早期 64 条 Match 评测不满足这个含义：它们只是 16 个基础样例的格式变体，而且基础样例曾进入训练池。因此相关结果已标记为 `HISTORICAL / INVALIDATED`，可以用于讲实验过程，不能作为独立泛化证据。正式 Gold V1 才是当前可信 holdout，但样本规模仍小。

## 实验如何判定有效

1. 训练前声明主指标和不可退化指标。
2. 固定数据版本、实体切分、代码、配置和随机种子。
3. 保存模型、输入、预测和报告哈希。
4. 先看格式和字段，再看 Product Final 业务指标和错例。
5. 偏好 loss、reward accuracy 或训练集指标只能说明优化过程，不能替代独立 Gold。
6. 小样本差一个案例就变化 0.04，必须报告样本数和错例，不能只报百分比。

## 长期回归规则

Gold V1 不继续人工改标签来配合实现，也不用于反复试规则。新数据到来后另建版本化扩展集；任何模型、归一化或规则变化都必须对 V1 做只读回归，并单独报告新集合结果。若只改善旧 Gold 而没有新集合证据，默认不进入产品。
