# 简历素材与项目亮点

## 项目标题建议

中文技术岗位可审计人岗匹配与大模型后训练系统

## 一句话描述

基于 Qwen3-14B、QLoRA 和 FastAPI 构建 JD/简历结构化与可解释匹配系统，以“模型抽取 + 确定性规则 + 模型解释”拆分生成能力和业务裁决，并建立来源分组、隐私准入、泄漏审计、训练门禁和分层 Gold 评测。

## 三条简历要点

- 设计中文 JD/简历/匹配多任务链路：使用 Qwen3-14B 4-bit QLoRA 做结构化抽取，以方向、技能、学历、年限和项目证据的 100 分规则引擎完成可审计裁决，并由模型生成一致解释；支持文本/文件/OCR、批处理、FastAPI 与 Vue 页面。
- 建立 pairwise 数据治理：按去标识化实体分组并“先切分、后配对”，将 Match 的跨集合实体泄漏降至 0；对 Resume 的格式/OCR 变体统一来源组，识别 15,470 行中 98.75% 来源组来自 bootstrap，避免以增强行数虚增数据多样性。
- 构建 25 条人工复核、五类训练重叠为 0 的 Match Gold V1，并冻结代码/模型/数据/报告哈希；Product Final 命中/缺失技能 F1 达 0.990649/0.986667，匹配等级和方向 EM 均为 0.96，同时因真实 Pair 与条件分布不足主动阻断新训练。

## 可按岗位选择的补充点

### 大模型算法/后训练

- 使用 4-bit NF4 QLoRA、DFT assistant-only loss 和对话模板训练多任务结构化模型；用 run manifest 记录 Git、配置、数据哈希和 readiness。
- 复盘 SFT→DPO 路线：DPO reward accuracy 0.9297 但未带来独立业务提升，因此增加 pause gate，避免用偏好训练指标代替产品指标。
- 将评测拆成 Raw、Normalized、Product Final，区分模型抽取、后处理和规则引擎贡献，避免效果归因失真。

### 数据工程/推荐搜索

- 把 Match Pair 建模为 JD—Resume 二部图，修复配对后随机切分造成的节点泄漏和巨型连通分量问题。
- 对公开数据执行许可、隐私、内容去重、来源、条件分布和真实 Pair 八维准入；FairCV 拒绝、`resume-ner` 降级为 audit-only。
- 建立 freshness、readiness 和 shell gate，让“数据管线可重建”与“数据允许训练”成为两项独立状态。

### 后端/AI 工程

- FastAPI 统一编排结构化生成、文件解析、OCR、规则评分和解释；Transformers 用生成锁保证单卡安全，vLLM 用 semaphore 和服务端调度实现受控并发。
- 使用 Pydantic、JSON Schema 和证据约束的后处理提高结构稳定性；支持 10 MiB 文件、20,000 字符正文和多种文档格式。
- 提供统一启停脚本、健康/预热/状态 API、批量接口和 Markdown 报告导出。

## 数字使用边界

- 必须同时写“Gold 25 条”，避免把小样本指标包装成大规模线上验证。
- 可以写“Match 五类训练重叠为 0”，不要写“完全无任何分布偏差”。
- 可以写 Product Final 0.96/0.99 指标，不要把 Raw→Final 归因于微调。
- 不要写“真实招聘 Pair 训练”，因为当前 4,798 Pair 全部合成。
- 不要写“生产部署”或“高并发”，因为当前是单机原型且没有冻结压测报告。
- 不要写“CI 全量通过”，仓库没有 CI；可写“构建本地自动化测试覆盖”。

## STAR 讲法

情境：非结构化 JD 和简历表述差异大，直接让模型给匹配分既不稳定又不可审计；公开简历还涉及隐私、许可和泄漏。

任务：构建一个可运行的人岗匹配原型，同时保证训练和评测证据可信。

行动：用 14B 模型做两侧结构化抽取，以确定性规则执行硬条件和技能证据，再让模型生成解释；为 Pair 建立实体级分组切分，为公开数据建立八维 readiness；重建人工 Gold 并冻结哈希。

结果：Gold V1 上最终技能 F1 约 0.99、等级/方向 0.96，五类重叠为 0；同时发现 Resume 来源集中、Match 全合成和年限分布单边，主动阻断了不可信的新训练。

## 面试中最值得强调的判断

项目亮点不只是“用了 14B 和 QLoRA”，而是发现高分背后的训练污染和数据伪多样性后，愿意推翻旧证据、重建 Gold，并让系统在数据不足时拒绝训练。这体现了模型工程、数据工程和产品风险判断的完整闭环。
