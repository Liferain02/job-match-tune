# 后训练与数据工程全流程

## 总体链路

```text
公开/自有候选源
  -> 许可与隐私准入
  -> 格式解析、字段归一化、内容去重
  -> 来源组/实体组标识
  -> 先分组切分、后任务配对
  -> SFT / preference 数据
  -> readiness 门禁
  -> QLoRA SFT
  -> 独立分层评测
  -> 有可靠偏好证据时才允许 DPO
```

关键不是“抓到多少行”，而是每行能否说明来源、许可、隐私、独立实体、条件覆盖和任务真实性。

## JD 数据

JD 来自受控公开源和导入文件，经过清洗、段落识别、字段规则、重复检测和方向冲突/年限缺失审计。数据构建保留 strict、repairable、supplemental 等质量层，而不是把所有抓取文本直接送入训练。当前 registry 中 JD 为 train 4,240、valid 530。

JD 的主要风险是职责与任职要求边界混淆。例如职责中出现 Agent，不一定代表硬要求技能。Product Final 的一个 Gold 错例正来自这个边界，而不是简单缺少词典。

## Resume 数据

原始简历先经历文件解析、OCR、章节归一化、隐私检测，再进入内容去重和来源组审计。格式或 OCR 变体共享同一 `source_group`，不能作为独立来源。

当前 Resume SFT 有 15,470 行、2,557 个有效来源组，其中 2,525 个来源组来自 bootstrap，占 98.75%。这比按文件变体虚增来源更诚实，也直接解释了 Resume readiness 为何不通过。

两个外部候选源的处理体现了“先准入、后扩量”：

- FairCV：1,000 条在隐私清洗后内容去重仅剩 1 条，且许可限制不适合训练，拒绝准入。
- `resume-ner`：3,821 条中大量含敏感信息，清洗和去重后虽有候选，但任务是 BIO NER，来源、标注和隐私证据不足，只保留 `audit_only`。

## Match Pair 数据

当前 Match SFT 的 4,798 个 Pair 全部由规则合成，人工训练 Pair 为 0，真实观察 Pair 为 0。显式年限条件样本有 1,944 条，全部是不满足，满足样本为 0。这意味着样本量看起来不小，但不能学习真实招聘偏好，也不能校准年限正负分布。

旧流程曾在配对后随机切分：1,200 个 JD 中 700 个跨集合，2,418 个 Resume 中 611 个跨集合；负样本复用还让 4,788/4,796 条边进入同一个连通分量。当前流程改为对去标识化、归一化后的 JD/Resume 实体做哈希和分组，先给实体分配 split，再只在同一 split 内配对，最终跨集合实体为 0。

## SFT 做什么

SFT 教模型遵守任务模板、输出字段契约并适应 JD/简历语言。当前多任务 registry 为：

| 任务 | train | valid |
|---|---:|---:|
| JD | 4,240 | 530 |
| Resume | 2,800 | 338 |
| Match | 2,600 | 320 |
| 合计 | 9,640 | 1,188 |

SFT 不是产品准确率证明。它只说明模型在指定数据分布上学会了结构和格式，产品价值仍要由独立 Gold 和规则层评测证明。

## DPO 在流程中的位置

DPO 通常在 SFT 之后：先让模型能稳定完成任务，再用 chosen/rejected 偏好对调整输出倾向。历史 DPO 在偏好数据上 reward accuracy 很高，但没有带来独立业务指标提升，所以当前结论不是“DPO 永远无效”，而是“本项目当前缺少值得继续 DPO 的产品证据”。

现有 DPO 数据管线保持暂停和过期状态，运行还需要显式 `JOBMATCH_ALLOW_DPO=1`。只有新增可靠偏好数据、SFT readiness 通过、且预先定义的 Gold 指标能判断收益时，才恢复。

## 数据获取和清洗的长期策略

每个新来源都执行相同的小闭环：

1. 记录 URL/文件、版本、采集时间、许可和允许用途。
2. 解析后立即做 PII/敏感字段审计，不先汇入大池。
3. 以内容而非文件名去重；格式、OCR、改写共享父来源组。
4. 统计真实实体数、来源集中度和关键条件分布。
5. Match 数据额外要求 Pair 的形成证据，区分真实观察、人工标注和规则合成。
6. 只有准入通过才进入候选池；只有 readiness 通过才构建训练数据。

这套流程可以持续接入数据，但不会因为“缺数据”就放宽许可、隐私或真实性标准。

## 当前停止条件

Resume、Match、Multitask readiness 均为 `false`，所以合理动作是保持现有模型和产品基线，等待新的合法、独立、去标识化 Resume/Match 数据。继续生成 bootstrap、格式变体或规则 Pair 只会增加行数，不会解决来源集中、真实 Pair 和条件分布问题。

## 与开源后训练框架的对照

- [TRL](https://github.com/huggingface/trl/blob/main/docs/source/dataset_formats.md)明确区分 language modeling、prompt-completion 和 preference 数据，并建议 DPO 使用显式 prompt。本项目保留 TRL，不再引入第二套 trainer；重点是让 SFT 与 preference 数据契约、来源和门禁分开。
- [LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory/blob/main/data/README_zh.md)用 `dataset_info.json` 注册文件、字段映射和 preference 属性。本项目对应地保留单一 `dataset_registry.yaml`，只记录实际生效的任务文件和数量，不复制完整框架。
- [Axolotl](https://github.com/axolotl-ai-cloud/axolotl)用 YAML 贯穿数据、训练、评测和推理，提供多种 LoRA/DPO 与分布式能力。本项目规模不需要迁移，吸收的是“配置可追溯”和“同一实验清单”的思想，落在 run manifest 与 readiness gate 上。
- [SkillSpan](https://github.com/kris927b/SkillSpan)的数据包含来源字段、专家标注和去标识化说明，且其实验显示多任务不天然胜过单任务。这对应本项目分别保留 JD、Resume、Match 指标，不用总 loss 证明三项任务都改善。

这些项目支持当前判断：训练器已经够用，主要优化空间在数据来源、任务契约、独立切分和业务评测，而不是再换一套后训练平台。
