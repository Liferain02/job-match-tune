# 面试深挖追问链

以下 16 组回答都以当前代码和证据为准。

## 1. 产品定位

Q1：这是聊天机器人吗？A：不是，是 JD/简历结构化、确定性匹配和受约束解释的可审计原型。  
Q2：为什么不用 LLM 直接打分？A：硬条件需要稳定复查，生成分会漂移。  
Q3：LLM 的价值在哪？A：处理非结构文本并把规则事实写成自然语言。  
Q4：最终边界？A：辅助用户发现差距，不替代招聘决策。

## 2. 完整调用链

Q1：一次匹配做几次生成？A：JD、Resume、解释共三次。  
Q2：为什么先两次解析？A：规则需要独立结构事实。  
Q3：谁决定匹配等级？A：`compute_match_rule_result`，不是解释模型。  
Q4：解析失败呢？A：停止后续评分，显式返回失败。

## 3. JD 证据边界

Q1：为何职责技能不能算必备？A：出现和硬要求语义不同。  
Q2：代码怎么保证？A：`collect_skill_evidence` 分 requirement/responsibility/bonus/other。  
Q3：模型输出 Kafka 就算吗？A：不算，模型字段只是候选，必须有要求段证据。  
Q4：代价？A：非标准 JD 可能少召回，但避免错误扣分。

## 4. OCR 技能归一

Q1：为什么不直接去掉所有空格？A：会制造子串假阳性和歧义。  
Q2：怎么做？A：只在 canonical 词表和唯一 compact key 内恢复。  
Q3：能处理什么？A：`Py thon`、`C + +`、`Node . js` 等。  
Q4：拼错怎么办？A：未知词不猜，独立样本证明后再扩规则。

## 5. 方向兼容

Q1：为什么不是简单相等？A：AI 平台等岗位有相邻工程方向。  
Q2：为何不能全设兼容？A：会把算法与普通后端错误合并。  
Q3：兼容需要什么？A：有限 taxonomy、职责上下文和至少两个共享技能。  
Q4：输出什么？A：exact/compatible/mismatch 和证据。

## 6. 启发式评分

Q1：66 分是什么意思？A：冻结权重下的规则总分。  
Q2：是 66% 录用概率吗？A：不是，`calibration_status=heuristic`。  
Q3：权重是多少？A：方向20、技能45、学历10、经验15、项目10。  
Q4：何时校准？A：获得合规真实 Pair 和招聘结果后。

## 7. JD/Resume 并行

Q1：两者能并行吗？A：逻辑上能，无相互依赖。  
Q2：为什么默认看起来顺序？A：Transformers 共享单模型并用生成锁。  
Q3：何时并行？A：vLLM 且并发槽至少 2。  
Q4：怎么确认？A：看 `/health` 的 `match_parse_mode` 和统一 benchmark。

## 8. 文件安全

Q1：只检查后缀吗？A：不是，检查魔数、容器结构和真实解码。  
Q2：伪 PDF 会怎样？A：返回 extension/content mismatch，模型不加载。  
Q3：这是安全沙箱吗？A：不是，没有杀毒和恶意文档隔离。  
Q4：为何仍有价值？A：阻止常见坏输入提前消耗 OCR/模型资源。

## 9. 数据切分

Q1：为什么随机 split 不够？A：同一实体的变体和配对会泄漏。  
Q2：怎么做？A：SourceGroup/Entity hash，先分实体再配对。  
Q3：近重复呢？A：normalized fingerprint 与 shingle/Jaccard 审计。  
Q4：零 hash 重叠是否充分？A：不充分，还需来源和人工检查。

## 10. SFT 与 QLoRA

Q1：SFT 学什么？A：三类任务的 JSON 格式和有证据内容。  
Q2：QLoRA 为什么？A：4-bit 基座加低秩参数降低 14B 训练显存。  
Q3：训练产物？A：adapter、checkpoint、日志、run manifest。  
Q4：现在为何不训？A：Resume/Match/Multitask readiness 未通过。

## 11. DPO

Q1：DPO 是 SFT 后一步吗？A：通常是，先有可用 policy 再学 chosen/rejected 偏好。  
Q2：能用合成 rejected 吗？A：可做链路验证，不能冒充真实偏好收益。  
Q3：人工 holdout 是什么？A：训练调参完全不可见的人工复核验收集。  
Q4：当前状态？A：偏好证据不足，pause gate 阻断。

## 12. Transformers 与 vLLM

Q1：默认选谁？A：默认 Transformers，部署简单、适合低并发验证。  
Q2：vLLM 优势？A：连续批处理和并发吞吐。  
Q3：为什么没直接切？A：当前环境未装 vLLM，缺同硬件实测。  
Q4：如何决策？A：同模型输入比较五类负载，同时跑 Gold 质量回归。

## 13. 三层评测

Q1：为何不只看 Product Final？A：无法区分模型和后处理贡献。  
Q2：三层是什么？A：Raw Model Derived、Normalized、Product Final。  
Q3：解释怎么评？A：结构一致与证据 grounding 分开。  
Q4：建议有效吗？A：当前无用户结果数据，明确 not evaluated。

## 14. Gold 与回归

Q1：V1 有多少？A：25 条人工复核样本。  
Q2：历史结果？A：最终等级和方向 exact match 均 0.96。  
Q3：现在还能叫 blind test 吗？A：不能，已查看后只叫 historical regression。  
Q4：如何得到新泛化结论？A：独立采样、盲标 Gold V2，冻结前不得调规则。

## 15. Readiness

Q1：数据多为何仍 false？A：来源、真实 Pair、条件分布比行数更重要。  
Q2：当前主要问题？A：Resume bootstrap 集中、Match 全合成、年限无满足正例。  
Q3：门禁在哪？A：`assert_training_readiness.py` 和训练 shell gate。  
Q4：怎么解除？A：获得合法独立去标识化真实数据并通过审计。

## 16. 过度设计取舍

Q1：为何不拆微服务？A：当前单机原型，一个编排服务仍可维护。  
Q2：为何不做账号/队列？A：不解决当前语义和数据证据瓶颈。  
Q3：做了哪些工程化？A：输入校验、锁定构建、统一脚本、环境约束、基准和测试。  
Q4：下一阶段核心？A：长期循环数据准入、清洗、分组、审计、门禁和独立评测，而非堆功能。
