# 踩坑到代码修复映射

| 发现的问题 | 根因 | 当前修复 | 验证 | 仍有边界 |
|---|---|---|---|---|
| `Py test` 等 OCR 断词漏召回 | 只做精确 alias | `skill_canonicalization.py` 的词表有界 OCR pattern | `test_skill_canonicalization.py` 正反例 | 未知拼写错误不猜测 |
| 职责技术被当必备技能 | 从整段 JD 扫技能绕过 section | `jd_skill_evidence.py` 保存四类证据，required 只认 requirement | `test_jd_skill_evidence.py` | 非标准栏目可能少召回 |
| 算法/后端方向过宽 | 单一 bool 和宽泛 alias | `direction_compatibility.py` 的 exact/compatible/mismatch + 双侧证据 | 方向兼容专项测试 | taxonomy 有限 |
| 分数像概率 | 权重/阈值无语义声明 | `MatchScoringPolicy` 冻结分项，标记 heuristic；UI 改称启发式分数 | scoring 与前端 smoke | 无真实结果不能校准 |
| 解释一致率含义过大 | 只看结构矛盾 | 拆 structural/evidence，advice validity 明示未评估 | `test_explanation_grounding.py` | 缺用户结果反馈 |
| JD/Resume 看似不能并行 | Transformers 用全局生成锁 | vLLM 下两解析并行；健康接口暴露 mode | server 并发测试 | 默认后端仍顺序 |
| 文件按扩展名进入解析 | 缺内容级校验 | 魔数、ZIP 结构、Pillow decode、UTF-8 控制字符前置校验 | upload/server 测试 | 不是恶意文件沙箱 |
| 前端依赖 CDN | 无 lockfile/build | Vue/Vite 本地依赖、package-lock、构建 smoke | npm build + smoke | 无浏览器 E2E |
| 数据随机切分泄漏 | 变体/配对共享实体 | SourceGroup 与 EntitySplit，先分实体再配对 | grouped split/audit | hash 不代表完全语义独立 |
| 合成数据规模掩盖证据弱 | readiness 只看格式/数量 | 来源、隐私、真实 Pair、分布、holdout 硬门禁 | readiness tests/reports | 受外部真实数据阻塞 |
| 看过 Gold 后仍报正式泛化 | 评测语境未区分 | `historical_gold_v1_regression` 警告并新文件重放 | run_match_eval tests | 必须建设独立 V2 |
| 后端性能凭感觉选择 | 工作负载不统一 | 同输入五类 API benchmark 和 GPU 快照 | benchmark tests | vLLM 环境尚未实测 |

这些修复都围绕主链路的语义正确性、可复现和可解释性，没有引入微服务、工作流平台或在线学习系统。
