# 数据治理、泄漏、隐私与 Readiness

## Readiness 不是一个样本数阈值

训练准入同时检查八类证据：格式、隐私、许可、来源、来源多样性、关键条件分布、真实 Pair 证据和跨集合泄漏。任一关键项不满足，就保持任务 `not_ready`；不允许用命令行开关把数据风险解释成训练工程问题。

## 当前状态

| 任务 | Readiness | 主要阻塞 |
|---|---|---|
| Resume | `false` | 2,557 个来源组中 2,525 个来自 bootstrap；有效候选池 2,845，小于目标 3,000 |
| Match | `false` | 4,798 Pair 全为规则合成；真实/人工训练 Pair 为 0；年限正例为 0 |
| Multitask | `false` | 继承 Resume 来源集中与 Match 条件、真实 Pair 缺口 |

SFT 派生管线当前是 fresh；DPO 管线按暂停策略保持 stale。`fresh` 只表示输入输出版本一致，不代表数据足以训练。

## 来源组为何比行数重要

同一份简历可以渲染为多种模板、OCR 噪声或文本格式。若把这些文件当成不同来源，训练和验证会同时看到同一内容，来源多样性也会被虚增。当前做法让所有派生变体继承根样本的 `source_group`，以内容实体而不是文件数计算独立性。

Resume SFT 的 15,470 行并不等于 15,470 个独立简历。2,557 个来源组和 98.75% bootstrap 占比才是决策需要的事实。

## 先切分再配对

Match 是二部图：JD 和 Resume 是节点，Pair 是边。只随机切边时，一个节点会通过不同边进入 train 和 valid；复用负样本还可能把几乎所有边连成一个大分量。

正确流程是：去标识化并归一化实体，计算稳定哈希；把相同/关联实体做 union；先给实体组分配 train/valid/test，再只在同一 split 内构造 Pair。Gold 审计还要同时查完整 Pair、Match 两侧实体和单任务数据三条路径。

## 隐私治理

简历是高风险个人数据。当前扫描电话、邮箱、微信、QQ、身份证、年龄、姓名语境，以及性别、婚育、户籍、出生、民族、地址、健康、政治面貌和个人账号等。训练数据中相关字段应删除，审计元数据只能保留必要、去标识化的信息。

“可以从网页下载”不等于“可以训练”。许可、隐私和用途限制是三项独立条件。FairCV 即使清洗后可读，也因重复和许可问题被拒；`resume-ner` 即使带 Apache 包元数据，也不能自动证明原始简历来源、当事人授权和标注适配。

## 合成数据的正确位置

合成数据适合启动字段格式、补极少数结构模式、做单元测试和 smoke test；不适合证明真实招聘匹配能力。合成数据必须标记父来源、生成方法和是否参与训练，不能与真实观察混为一类。

当前 4,798 个规则 Pair 全合成，因此 Match readiness 失败是预期的保护，不是脚本故障。下一批有效数据应优先补：真实或人工独立 Pair、年限满足正例、跨方向可迁移案例和合法独立 Resume，而不是再扩合成数量。

## 新数据到来时的最小验收单

- 能说明数据所有者、许可、版本、取得时间和允许用途。
- 原文与元数据均通过隐私扫描；抽样人工复核脱敏结果。
- 内容哈希去重后仍有足够独立实体；派生样本继承来源组。
- 训练、验证、Gold 的实体/Pair 五类重叠均为 0。
- 关键条件有正负覆盖，尤其学历、年限、方向和技能证据。
- Match Pair 能区分真实观察、人工判断和规则合成。
- 报告 readiness JSON，并由 gate 阻止未通过任务。

## 何时允许恢复训练

只有新加入的合法、独立、去标识化 Resume/Match 数据使相应 readiness 全部通过，才进入训练。阈值和隐私规则不因赶进度而下调；在外部条件未变化时，持续审查的正确输出可以是“无新证据，保持停止”，而不是制造新功能。
