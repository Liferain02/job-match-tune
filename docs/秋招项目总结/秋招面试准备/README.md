## 三种时间安排

### 只有两小时

读项目定位、请求生命周期、训练评测泄漏、评测污染、数据不足停止决策，再看数字速查。目标是讲清核心架构和三个最有含金量的挑战。

### 有一天

按七个目录顺序阅读。手算一次评分、手画一次并查集、复述一次DFT/DPO区别，然后随机挑三个难点，用“问题—证据—修复—验证—边界”讲五分钟。

### 面试前十五分钟

只看数字速查、30秒项目口述和三个STAR故事。不要在临场重新学习公式。

## 面试中的可信表达原则

- 先讲问题和约束，再讲框架与算法。
- 明确区分模型原始输出、确定性后处理和产品最终结果。
- 指标必须同时说明样本规模、评测层级和是否after inspection。
- 不把15,470条格式样本说成15,470份独立简历。
- 不把启发式匹配分说成录用概率。
- 不把规则合成Pair说成真实招聘匹配数据。
- 不把结构一致率当建议业务有效性。
- Readiness=false和暂停DPO是工程判断，不是需要隐藏的失败。
