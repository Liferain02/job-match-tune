# 评测污染与指标可信度：从高分到冻结回归

## 1. 最危险的不是低分，而是解释错误的高分

项目有25条人工复核 Match Gold。历史产品结果在技能和硬条件上已较高，修复边界错例后结构字段达到1.0。

如果只看数字，很容易写成：

> 匹配准确率达到100%。

但开发者已经查看这些错例并根据它们修改规则。此时它们不再是 blind holdout。

## 2. 指标污染是怎么发生的

典型过程：

```text
在测试集运行
→ 打开错例
→ 修改规则/alias/prompt
→ 再在同一测试集运行
→ 选择表现最好的版本
```

即使没有把测试样本放进梯度训练，它也参与了人工模型选择，因此已经成为开发集。

## 3. 最初只报最终指标的问题

产品最终结果结合了：

- 模型原始抽取；
- JSON修复；
- 字段归一化；
- 技能证据重建；
- 方向和评分规则。

只报 product final 无法知道高分来自模型还是后处理，也无法发现模型升级后 raw 能力退化但规则恰好掩盖。

## 4. 三层评测如何解决归因

### Raw model derived

JD和简历必须原生 strict JSON 成功，直接使用 `raw_data` 计算规则。

### Normalized

使用有限 JSON repair 和业务归一化后的结构计算规则。

### Product final

使用实际线上规则结果，并检查最终解释。

同一字段在三层都有指标，差异就是后处理贡献和产品闭环贡献。

## 5. 结构正确仍不代表解释可信

解释评测再拆成：

```text
structural consistency：是否与规则布尔和等级矛盾
evidence grounding：技能与硬条件陈述是否有证据
advice validity：建议是否真的提升求职结果
```

当前冻结回归结构一致率为1.0，grounding为0.92；advice validity明确不评，因为没有用户采纳和投递 outcome。

这防止用“语言听起来合理”替代业务有效性。

## 6. Gold 审计具体检查什么

`audit_match_gold` 不只数行数：

- 每行 label 类型；
- matched 和 missing 是否交叉；
- id/source group/pair 是否重复；
- annotation status 是否 human_verified；
- annotator、时间、rationale 是否存在；
- 九类 difficulty tags 是否覆盖；
- pair、JD、Resume 是否与训练重叠；
- JD/Resume 单任务数据是否重叠。

满足这些门槛才得到 `gold_ready=true`。

## 7. `gold_ready=true` 为什么仍不能证明盲测

该字段说明数据结构、人工状态、最小规模和精确hash独立性通过审计；它不记录“开发者是否已经看过答案并调过系统”。

所以报告额外引入：

```text
evaluation_validity = historical_gold_v1_regression
warning = REGRESSION AFTER INSPECTION
```

这是评测语义治理，而不仅是数值计算。

## 8. 单审核者问题

25条样本全部由同一审核者复核。即使每条都有 rationale，也无法估计：

- 不同标注者对 compatible 的分歧；
- required/bonus 边界的一致性；
- 匹配等级阈值是否符合招聘方；
- 标签是否受当前系统设计影响。

因此更成熟的下一版应使用双人独立标注和争议裁决，而不是只增加同一人的标注量。

## 9. 新人工 holdout 应如何冻结

```text
从未进入训练的新来源
按JD和Resume实体隔离
标注时不显示当前预测
预先固定口径
两人独立标注
记录disagreement与裁决
保存数据hash与冻结时间
最终比较前不看逐条答案
```

一旦打开错例并修改系统，它就降级为下一轮冻结回归集；然后需要新的blind holdout。

## 10. 为什么不是用另一个 LLM Judge 代替人工

LLM Judge 可以做候选筛选或发现明显矛盾，但它可能：

- 偏好更长、更流畅的回答；
- 与被评模型共享偏差；
- 无法知道真实招聘口径；
- 对技能可迁移和硬门槛给出不稳定判断。

在小型高风险边界集上，人类双标比再引入一个模型更直接。

## 11. 正确的指标表达

完整表达需要同时包含：

```text
数据规模：25条
标注状态：人工复核，单审核者
评测层：product final
结果：结构字段回归1.0，grounding 0.92
有效性：after inspection冻结回归
未评部分：建议业务有效性
```

缺任何一项，都可能造成不当解读。

## 12. 面试回答结构

> 最初我也会关注最终高分，但后来意识到查看测试错例并调规则后，同一集合就不再是blind holdout。我把评测拆成raw、normalized和product final三层，并在报告里显式标记`historical_gold_v1_regression`和`REGRESSION AFTER INSPECTION`。当前25条冻结回归的结构字段是1.0，但解释grounding只有0.92，建议是否提升投递结果没有数据支持。下一轮要建立新来源、双人标注且在最终比较前不打开答案的人工holdout。
