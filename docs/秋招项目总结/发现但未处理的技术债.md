本轮只整理文档，不修改产品行为。以下是继续维护时应知晓的限制，不代表现在都应立项。

## 当前高价值但受外部条件阻塞

- Resume 独立来源不足，Match 没有真实/人工训练 Pair，年限样本没有满足正例。处理条件：获得合法、独立、去标识化数据。
- Gold V1 仅 25 条，适合冻结回归，不足以覆盖岗位、行业和人群分布。处理条件：独立新增人工标注，不在原集合上继续调规则。

## 运行和工程限制

- FastAPI 编排集中在单个 `server.py`，当前规模可维护；若未来接入鉴权、任务队列或多模型路由，再按职责拆分。现在拆微服务属于过度设计。
- Transformers 后端用全局生成锁，低并发安全但吞吐有限。vLLM 有受控并发实现，但尚无冻结的目标硬件压测报告。
- 前端通过 CDN 加载 Vue ESM，无构建链和锁定依赖；适合演示，离线或生产部署会受 CDN 可用性影响。
- 文件上传主要依赖扩展名和解析结果，没有完整的内容级 MIME/恶意文件检测；不要把服务暴露为公共匿名上传端点。
- 默认 CORS 面向本地演示，系统没有账号、鉴权、配额和审计日志，不适合直接公网多租户部署。
- 仓库有较广的本地测试，但没有 CI 配置、真实浏览器端到端和已冻结 vLLM 性能基线。

## 模型和规则边界

- 技能别名与 OCR 归一化仍是有限词表；Gold 中 `Py test` 未恢复为 Pytest。只有新独立样本反复证明是通用错误时才扩规则。
- 岗位方向使用有限 taxonomy，相近 AI 后端/算法平台存在边界误差。若产品进入更多岗位，应先定义人工口径和层级 taxonomy，再改实现。
- JD 职责和要求边界偶尔会把职责技术当成硬技能。需要更多独立边界案例，而不是对单条 Gold 加关键词。
- 规则分数和 85/65/45 阈值是产品启发式，不是从真实招聘结果校准；在获得真实 Pair 前不做伪精确概率解释。
- 解释一致率只检查与结构化结果一致，不代表建议在真实求职中必然有效。

## 复现边界

- 当前 run manifest 能记录新训练的 Git/配置/数据事实，但历史冻结报告并非所有信息都在报告正文中，需要结合冻结文档和文件哈希解释。
- Gold 冻结 commit 与当前文档 commit 不同是正常现象；不得重算旧哈希来“同步”当前仓库。
