# 踩坑复盘与关键优化

## 1. 把格式变体当成数据多样性

早期同一基础简历被渲染成多种格式和 OCR 变体，文件数上涨，但语义来源没有增加。如果随机切分，这些近重复内容还会跨 train/valid。

优化后，派生样本继承根样本的 `source_group`，readiness 按有效来源组而不是文件行数判断。结果是指标看起来更保守，但决策更真实：15,470 行 Resume SFT 中，98.75% 来源组仍来自 bootstrap。

## 2. 配对后随机切分造成图泄漏

Match Pair 不是相互独立的文本行。一个 JD 或 Resume 被复用于多条正负 Pair 时，随机切边会让同一实体进入不同集合；历史数据甚至形成包含 4,788/4,796 条边的巨大连通分量。

优化是先按归一化实体哈希分组、处理关联分量并分配 split，再只在 split 内配对。Gold 还额外做五类重叠审计。这个经验可迁移到推荐、搜索、风控等所有 pairwise 数据任务。

## 3. 把合成 Pair 的规模当成业务证据

规则可以快速产生大量正负 Pair，但它只会把现有规则偏好教回模型，也不能表示真实招聘决策。当前 4,798 个 Pair 全合成、人工训练 Pair 和真实观察 Pair 都是 0。

优化不是再设计一个更复杂的合成器，而是让 readiness 直接失败，并把下一次训练绑定到真实/人工独立 Pair 的外部条件。

## 4. 历史“人工留出集”并不独立

早期 64 条 Match 评测由 16 个基础案例做格式扩展，而且基础案例进入过训练。即使后来人工看过标签，也不能恢复为独立 holdout。

处理方式是保留历史实验但标记 `INVALIDATED`，重新建立 25 条人工复核、五类重叠为 0 的 Gold V1，并冻结代码、模型、数据、报告和预测哈希。重点不是删除不好看的历史，而是把证据等级说清楚。

## 5. 只看最终分数，错误归因给模型

如果只看 Product Final，会把 JSON 修复、方向归一、技能证据和规则评分的提升都算在微调模型上。Raw 的技能和方向明显较低，说明工程层贡献很大。

优化是统一报告 Raw、Normalized、Product Final，并确保 Raw 的定义是“原始解析 + 同一固定 scorer”，不是另一个不透明模型。这样才能决定该补数据、改后处理还是改规则。

## 6. DPO 训练指标好，不代表产品提升

历史 DPO 的 reward accuracy 和 margin 较好，但独立业务指标没有超过 DFT/SFT。偏好数据又主要来自规则和 bootstrap，因此训练目标与真实用户偏好之间存在循环证明。

优化是暂停 DPO 派生管线，增加显式运行开关，把恢复条件设为：可靠偏好对、SFT readiness 通过、预先定义的独立业务指标能判别收益。

## 7. 为小 Gold 追求 100 分

当前三类错例都能通过专用别名或方向映射修掉，但 25 条集合每修一条就提升 0.04。针对已知 Gold 写规则会把评测集变成开发集。

因此没有加入 `Py test -> Pytest`、特定 AI 方向等样例补丁。更好的做法是在新独立集合中观察同类错误是否反复出现，再做通用改动。

## 8. 无条件并行 GPU 推理

JD 与简历业务上独立，但默认 Transformers 后端共享一个模型和 GPU。直接用线程并行可能增加峰值显存、破坏生成状态或让吞吐更差。

实现选择是 Transformers 加锁串行，vLLM 由调度器受控并发。同一个业务流程根据运行后端采用不同调度策略，避免把“并行”当成必然优化。

## 9. 抓取可达不等于训练可用

公开简历源可能有 PII、用途限制、重复模板或任务格式不匹配。FairCV 和 `resume-ner` 的审计说明，下载成功只是候选发现，不是训练准入。

优化后将许可、隐私、内容去重、来源和任务适配拆成独立门槛；不通过的数据保留审计结论，不进入训练池。

## 10. 原型范围不断膨胀

人岗产品很容易扩到账号、职位库、候选人管理、工作流和推荐系统，但这些功能不会解决当前的证据瓶颈。

当前收敛为三条核心流：解析 JD、解析简历、可解释匹配。下一阶段不做平台化重构，先等数据 readiness 改变。这是产品优先级选择，不是工程能力不足。

## 可复用的方法论

- 行数、文件数、增强数都不能替代独立实体数。
- 对 pairwise 任务先切实体再配对。
- 数据许可、隐私和任务真实性必须在训练前审计。
- 评测要按流水线分层，最终分数要能追溯到各组件。
- 训练 loss 是诊断量，独立业务指标才是决策量。
- 小样本 Gold 用来守回归，不用来反复调参。
- 停止错误实验也是有效优化。
