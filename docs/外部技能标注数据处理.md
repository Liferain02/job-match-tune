# 外部技能标注数据处理

更新时间：2026-08-09

## 1. 为什么接入这两套数据

当前 JD SFT 的 `必备技能` 主要来自规则、公开弱标注和完整 JD 标签，适合端到端 JSON 解析，但缺少独立、跨度级的技能抽取 gold。继续增加完整 JD 行数无法回答“模型到底有没有找对技能边界”。

本轮选择：

- `Chinese-SkillSpan`：与中文招聘核心场景直接相关，按 Language、Knowledge、Skill、Transversal 四类标注，论文说明使用 LLM 辅助和专家复核。
- `SkillSpan`：NAACL 2022 英文招聘技能数据，由领域专家标注，MIT 许可证，上游说明已按 GDPR 去标识。

没有采用新的大规模简历匹配数据。检索到的多数候选是全合成、教师模型打分、真实简历来源不明或许可证缺失，质量证据不足。

## 2. 可复现下载

数据清单位于 `configs/external_skill_gold_sources.yaml`：

- 所有文件保存上游 URL 和 SHA-256；
- 英文 SkillSpan 固定到 commit `2ccf3de5b5af7a5409b8dd814fb1315dd6e0ae1b`；
- Chinese-SkillSpan 的 Google Drive 文件没有稳定 revision，因此以 SHA-256 固定内容；
- 原始和处理数据都在 Git 忽略的 `data/external/`，不会误提交。

执行：

```bash
conda activate tune-demo
bash scripts/data/prepare_external_skill_gold.sh
```

输出：

```text
data/external/skill_gold_raw/
data/external/skill_gold_processed/
outputs/eval_reports/external_skill_gold_report.json
```

## 3. 处理规则

### 中文数据

1. 只处理带人工复核标注的 dev/test；上游 train 文件的 1204 条没有跨度标签，保留原始文件但不伪造监督。
2. 将 `@@片段##[L|K|S|T]` 转为原句字符 offset 和四类技能列表。
3. 标注文本必须能无损还原输入原句，否则剔除。
4. test 优先于 dev；删除 split 内重复文本和跨 split 重复文本。
5. 同一 `job_id` 不得跨 split。

### 英文数据

1. 从两层 BIO 标注分别恢复 soft skill 和 knowledge span。
2. token 数与 tag 数必须一致；非法 `I` 起始不自动猜测，直接剔除。
3. 上游说明 `idx` 在每个 split 重新编号，因此不能把不同 split 的相同 idx 当成同一职位；改用文本 hash 检查跨 split 重复。
4. test、dev、train 依次保留，低优先级 split 删除重复文本。

## 4. 实际审计结果

| 数据 | 原始规模 | 处理后 | 技能跨度 | 破损标注 | 去重与隔离 |
| --- | ---: | ---: | ---: | ---: | --- |
| Chinese-SkillSpan | train 1204、dev 2142、test 2676 | dev 2019、test 2483 | 12804 | 86（1.78%） | split 内删除 195，跨 split 删除 35 |
| SkillSpan | train 4800、dev 3174、test 3569 | train 3697、dev 2428、test 2659 | 9316 | 1（0.01%） | split 内删除 1045，跨 split 删除 1713 |

处理后的两套数据：

- 跨 split source group 为 0；
- 跨 split 文本 hash 为 0；
- test 均非空；
- 原始破损率低于当前 2% 的外部评测接入阈值。

英文数据大量被去重，是因为职位模板、标题和无技能短句在不同职位及 split 中反复出现。保留这些重复项会让评测结果被模板句放大，因此没有追求上游行数。

## 5. 使用边界

`Chinese-SkillSpan` 当前只允许内部评测：公开页面和论文说明了数据来源、标注流程与下载地址，但没有找到明确的数据许可证。许可证确认前：

- 不进入 SFT/DPO；
- 不复制到版本化 `data/eval/`；
- 不对外重新分发处理结果。

`SkillSpan` 许可证明确，但它是英文跨度任务，与当前中文完整 JD JSON schema 不同。本轮同样只用于外部评测，后续只有在独立实验能证明提升且不损害中文主任务时，才考虑增加辅助训练任务。

## 6. 简历 NER 的同步处理

现有 `PassbyGrocer/resume-ner` 的 0～16 数字标签已恢复为 `B-NAME`、`B-ORG` 等可读 BIO 标签。审计发现 3821 行中有 3375 行含姓名、联系方式、地点、机构或民族类实体。虽然上游声明 Apache-2.0，数据卡没有说明原始来源、授权与脱敏流程，所以该数据继续保持 `audit_only`，不能因为标签完整就进入简历训练。
