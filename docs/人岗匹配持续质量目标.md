# 人岗匹配持续质量目标

> 当前状态（2026-08-13）：Match Gold V1 已冻结为 25 条，`human_verified_rows=25`、`gold_ready=true`。Product Final 命中技能 F1 0.990649、缺失技能 F1 0.986667、匹配等级 EM 0.96、方向 EM 0.96，学历、年限和解释一致率均为 1.0。本文第一至第八轮中的 `human_verified_rows=0` 是当轮历史快照，不是当前状态；完整当前口径见[秋招项目总结](秋招项目总结/README.md)。

## 目标

本项目不再以“再训练一次”作为阶段终点。持续目标是：用独立、人工复核、与训练数据隔离的人岗匹配 Gold 集发现真实错误，每轮只修复最高频的 1—2 类核心问题，并复测 JD 解析、简历解析、人岗匹配三条主流程。

固定循环如下：

```text
补充并人工审核难例
        ↓
Gold 防泄漏与标注完整性审计
        ↓
Raw Model / Normalized / Product Final 三层评测
        ↓
统计真实错误，选择最高频 1—2 类
        ↓
做最小的数据、清洗、归一化或规则修复
        ↓
复测 JD / 简历 / 匹配，记录增益与回退
        └──────────────────────→ 下一轮
```

这个 goal 保持运行，不因一轮数据构建、一次测试通过或一份报告生成而结束。只有用户明确结束，或者连续多轮都因缺少人工标注或外部状态变化而无法继续时，才结束或报告阻塞。

## 当前基线是否可信

截至 2026-08-12，旧 Match 评测由 16 个基础样例扩成 64 个格式变体；同一批基础样例还曾被扩写进匹配训练池。因此历史 64 条报告不能再作为独立泛化证据。

当前已完成：

- 删除旧的 `match_manual_train_pool.jsonl` 生成链路；
- 重新构建匹配训练池后，候选评测集与训练集的文本对重合从 16 条降为 0 条；
- 建立 25 条审核候选，覆盖九类目标难例；
- 候选全部禁止进入训练，并且不会因 AI 草拟标签自动成为 Gold。

当前已完成：25 条候选全部经过人工复核，`human_verified_rows=25`、`gold_ready=true`，并冻结为 Match Gold V1。它可以作为正式开发回归基线，但由于样本量只有 25，仍不能等价为大规模真实招聘质量。

匹配训练池当前另有一个明确限制：4,798 条均为规则配对生成的 `synthetic_text`，真实或人工训练 Pair 为 0。它可以用于验证输出格式和训练链路，但不能证明真实匹配质量。readiness 现在把 `match_real_pair_quality_evidence_ready=false` 纳入 Match SFT 门禁，不再让“数量/格式可训练”冒充“真实质量证据充分”。本阶段不因此新增数据抓取器；外部数据必须先满足准入、脱敏和独立复核条件。

## 人工 holdout 是什么

人工 holdout 即“人工标注的独立留出评测集”。它像一份最终考试卷：

- JD 和简历对由人工给出正确匹配结论；
- 样例及其近重复不参加训练，不用于生成 preference，也不用于反复调标签迎合当前模型；
- 可以根据错例类型决定下一轮优化方向，但不能把同一条样例答案直接回灌训练后继续在原题上宣称提升；
- 做过针对性优化的样例仍可用于回归，但新一轮泛化结论还需要新增、未参与调试的样例。

这里的“人工”不能由模型自评替代。AI 可以整理候选和草拟理由，但必须保留 `needs_human_review` 状态。

## 人工审核步骤

先生成不会被日常 builder 覆盖的私有审核文件：

```bash
bash scripts/data/prepare_match_gold_review.sh
```

默认审核文件为 `data/private/match_gold.jsonl`。每行是一组 JD、简历、草拟标签和难例类别。该脚本发现目标已存在时会直接保留，不会覆盖人工修改；`data/eval/match_gold_review_candidates.jsonl` 只是可重建模板，不应直接在其上长期标注。

人工逐行检查以下内容：

1. `匹配等级` 是否综合反映方向、技能和硬门槛，而不是只看技能数量。
2. `岗位方向匹配` 是否根据职责和项目证据判断，而不是只比较岗位名称。
3. `学历匹配`、`经验匹配` 是否严格遵守文本中的明确硬门槛。
4. `命中技能` 是否存在直接证据；同义词可视为命中，可迁移但不等价的技能不能伪装成已掌握。
5. 技能在项目中出现也算证据；仅由常识推测、原文未出现的不算。
6. 修改错误标签后，把 `meta.annotation_status` 改为 `human_verified`，填写真实的 `annotator_id`、`reviewed_at` 和 `rationale`。

不要修改 `training_eligible=false`。完成后运行：

```bash
bash scripts/data/audit_match_gold.sh --gold data/private/match_gold.jsonl
```

如果要先看最值得审核的样例及其年限、学历、技能证据：

```bash
bash scripts/data/build_match_review_queue.sh
```

结果写入 `outputs/eval_reports/match_gold_review_queue.json`。它只排序并展示证据，不自动修改标签。

只有报告同时满足以下条件才可称为 Gold：不少于 20 条、全部人工复核、九类难例均覆盖、ID/来源组/文本对无重复，并且完整配对、单独 JD、单独简历都不与 Match/JD/Resume 任一训练池重合。

## 三层指标口径

| 层 | 实际测量对象 | 用途 |
| --- | --- | --- |
| Raw Model | 模型原始输出必须是严格 JSON，不做 JSON 修复和业务归一化；再用同一个固定评分器派生结构化结果 | 区分模型原始抽取能力与后处理贡献 |
| Normalized | 对 JD 和简历解析结果做现有字段修复、技能别名和格式归一化，再运行固定评分器 | 测量清洗与归一化后的结构化质量 |
| Product Final | Normalized 的结构化结果，加上最终生成的匹配解释 | 测量用户实际看到的结果和解释一致性 |

本项目当前的匹配模型只生成解释，不直接生成匹配等级。因此 Raw Model 层的匹配指标是“原始解析结果经固定评分器派生”，不能写成纯模型匹配准确率。

## 固定错误分类

每轮至少统计：技能漏召回、技能误识别、同义表达错误、可迁移技能错误、岗位方向错误、匹配等级错误、模型解释与结构矛盾、输出格式错误。学历和经验判断错误另行保留，因为它们通常是产品硬门槛。

一次只选择最高频的 1—2 类。若问题来自技能同义词，优先补现有 alias；若来自 OCR，优先补最小规范化；若来自标签口径，先修 Gold，不训练模型。禁止为了单个样例引入新的框架、向量库、复杂规则 DSL 或新的抓取系统。

## 本阶段暂停项

当前继续暂停新增 DPO。虽然可信 Gold 和首轮错误分析已经完成，但 Resume/Match/Multitask readiness 仍未通过，也没有新的人工 preference 或独立业务收益证据。DPO 脚本默认被门禁阻止；只有这些外部条件改变并明确恢复实验时，才可用 `JOBMATCH_ALLOW_DPO=1` 临时解锁。历史 checkpoint 保留用于复现，不作为当前默认产品升级依据。

## 第二轮执行记录（2026-08-12，HISTORICAL）

第二轮没有继续调整匹配等级。先对第一轮剩余 5 条分歧生成证据审核队列，结果显示：

- `match_eval_001`、`match_eval_002` 的标签把“没有明确年限证据”标成了经验满足；
- `match_eval_008`、`match_eval_016` 把已有 OCR 技能证据标成了缺失；
- `match_gold_candidate_007` 是算法平台与 AI 后端的方向口径争议，需要人工决定。

因此当前剩余分歧没有足够证据支持继续改规则。

数据审查另发现两类可以独立证明的问题：

1. 年份曾被误当成经验时长。教育信息中的 `2023年毕业` 或 `26年毕业` 会错误通过经验门槛；现已排除日历/毕业语境，并让 `3–7年` 取下限 3 年作为最低要求。重建后 65 条合成 Match 标签从经验满足改为不满足，其中 40 条匹配等级随之修正。
2. Match 配对绕过了 Resume SFT 的隐私清洗。原 4,798 条配对中有 747 条含个人资料或敏感字段；清洗后隐私发现数为 0，去重池从 4,798 条降为 4,698 条，说明其中 100 组所谓差异只来自个人资料。
3. Match 中 4,277 / 4,698 条 JD 携带上游“从岗位中提取学历”任务包装，教育弱来源占比约 91%。现在仅删除这两类明确包装行，并对该来源家族设 40% 上限。重建后合成池为 4,800 条，教育来源 1,920 条；脱敏简历来源重建、去重并在最终产物复核上限后，组合池为 4,798 条，教育来源 1,919 条（39.9958%），包装文本和隐私发现均为 0。这个上限只防止单一弱来源统治训练池，不把合成数据改称为真实配对。

清洗还证明当前 Resume 数据量存在严重虚高：1,000 条 FairCV 简历清除个人资料后只剩 1 个独立内容模板；并且该源在配置中本来就是许可未确认的 `candidate_pool_only`，旧组合池却漏做了准入检查。修复后这 1,000 条全部退出训练，Resume 组合池从 4,292 降为 3,292，SFT 最终为 51,248 个格式样本、2,652 个来源组，约 95.17% 来自 bootstrap。系统现在如实报告 `resume.profile_ready=false`、`multitask.source_diversity_ready=false`，不会通过降低阈值或调整任务配比让报告变绿。DPO 和新 SFT 继续暂停。

年限与隐私修复在保存的 25 条候选解析结果上重放后，三层 Match 指标、5 条剩余分歧和解释一致率均保持不变。

本轮最终验收：392 个 Python 测试、Ruff、Python 编译、Shell 语法和前端报告冒烟测试全部通过。`sft_pipeline_fresh=true`；因本 goal 暂停而未重建的两条 DPO 派生数据单独报告为过期。总训练门禁仍关闭，明确原因是 Resume 原始来源多样性和多任务 Resume 来源比例不足，不是格式、隐私或 Match 条数不足。

## 第三轮执行记录（2026-08-12，HISTORICAL）

第三轮继续审查泄漏，发现旧 Match SFT 只按完整配对 ID 分组。完整 JD—简历对的跨 split 重复确实为 0，但组成它们的实体大量泄漏：

- 1,200 个独立 JD 中 700 个跨 split，占 58.33%；
- 2,418 份独立简历中 611 份跨 split，占 25.27%；
- 由于随机负配对复用简历，旧配对图中 4,788 / 4,796 条边连成一个巨大组件，无法在下游通过换一个 group key 补救。

修复没有引入新拆分框架：在生成配对前，分别按脱敏和规范化后的 JD/简历内容哈希切成 train/valid/test，仅在同一 split 内选正负简历。教育弱 JD 与其他 JD 分层切分，保持每个 split 的来源比例。重建后：

- Match SFT 为 train 3,838 / valid 480 / test 480；
- 1,200 个 JD 实体、2,409 个简历实体，跨 split 数均为 0；
- 教育弱来源分别为 train 1,535 / valid 192 / test 192，总占比 39.9958%；
- readiness 新增 `cross_split_linked_source_groups`，Match 和多任务中任一 JD/简历实体跨 split 都会直接阻断 SFT。
- Gold 审计从只检查完整配对，扩展为同时检查 Match 池中的 JD/简历实体，以及 JD 和 Resume 单任务池。当前五种重合计数均为 0。

这一轮没有修改评分器或结构标签。另外确认两个不依赖 Gold 口径的产品标签缺陷：

1. 4,798 条 Match SFT 的“推荐投递岗位方向”100% 是“当前 JD 对应方向”、“技能相近岗位”等五种占位语，没有一条是真实方向。现在直接使用配对时已有的规范 JD/简历方向，重建后覆盖后端开发、算法工程等 16 个实际方向，占位语为 0。
2. 4,798 条配对中 2,529 条（52.71%）已有评分器确认的 `命中项目`，但旧 Match SFT prompt 和目标答案均 0 条使用它，造成训练/推理 schema 不一致。现在所有 prompt 都显式包含该字段，2,529 条目标答案会将具体项目证据写入匹配优势。

readiness 在 Match 和多任务两处都对占位推荐和项目字段丢失设置 0 容忍门禁。候选 Gold 的 5 条分歧仍保持人工待审状态。

## 第四轮执行记录（2026-08-12，HISTORICAL）

本轮没有继续追逐候选 Gold 上的 5 条争议，而是审计 4,798 条合成 Match 标签中的学历硬约束。发现两处同源错误：`研究生` 没有进入学历等级表；学历提取按正则类型优先，导致“本科及以上学历，硕士优先”被后面的“硕士优先”覆盖。旧池因此有 214 条学历标签与输入语义不一致，其中 54 条误放行、160 条误拒绝，并导致 76 条匹配等级变化。

readiness 新增 Match 学历一致性门禁：用产品当前的学历判断重放 `jd_text`、`resume_text` 与训练标签，存在任一矛盾即阻断 Match SFT。当前 4,798 条矛盾数为 0。保存的 25 条候选模型输出重放后，三层指标不变：Raw Model 有 24 条差异，Normalized/Product Final 有 5 条差异，Product Final 匹配等级准确率 0.92、命中技能 F1 0.984、学历准确率 1.0、解释一致率 1.0。这些仍是未人工复核候选诊断，不是正式产品准确率。

`sft_pipeline_fresh=true`，DPO 派生数据按本 goal 的暂停要求保持过期且不可执行。Gold 五类训练重叠均为 0，但 `human_verified_rows=0`，因此当前仍不能声称真实人岗匹配质量已经验证。

本轮验收：396 个 Python 测试、Ruff、Python 编译、全部 Shell 语法和前端报告冒烟测试通过。

## 第五轮执行记录（2026-08-12，HISTORICAL）

本轮转向 Resume 数据获取和模板膨胀。旧 Resume SFT 将每个来源手工渲染为 20 种格式，得到 51,248 条样本，但只有 2,652 个来源组，扩写倍数 19.32。只读模拟发现，过多模板还会与其他来源发生内容碰撞，使部分来源组在全局去重时消失。

按“核心输入形态而非模板数量”收缩为 6 种：原文、标准卡片、列表、紧凑、OCR、中英混合；同时删除其余 14 个不再使用的渲染器。进一步检查发现 freshness 图漏掉了 synthetic Resume 生成器代码，导致第一次局部重建仍把 448 条旧模板误当成来源；补齐依赖并完整重建后，synthetic pool 从 3,200 降为 960，组合池从 3,292 降为 2,844。Resume SFT 为 train 12,339 / valid 1,565 / test 1,560，共 15,464 条，比 51,248 条旧集减少 69.83%；来源组仍为 2,652，扩写倍数从 19.32 降为 5.83。

门禁没有为了结果变绿而放宽数据来源要求：2,652 个 Resume 来源组中仍有 2,524 个（95.17%）来自 JD bootstrap；多任务 Resume 来源组比例仍为 train 0.7575 / valid 0.7870，所以 `resume`、`multitask` 继续阻断总 SFT。Match 随来源变化重建为 4,797 条（train 3,839 / valid 479 / test 479），学历标签矛盾和实体跨 split 均为 0。下一步的数据获取目标是补充合法、脱敏、内容独立的简历来源，而不是继续生成格式变体。

本轮验收：397 个 Python 测试、Ruff、Python 编译、全部 Shell 语法、前端报告冒烟和 `git diff --check` 通过；新 Match 池与 Gold 的五类重叠均为 0。

## 第六轮执行记录（2026-08-12，HISTORICAL）

本轮核对现有两个中文公开简历候选的上游状态。FairCV 数据卡仍未声明许可证，并且本地 1,000 条样本脱敏后只有 1 个内容模板，继续限定为 `candidate_pool_only`。`PassbyGrocer/resume-ner` 的仓库元数据声明 Apache-2.0，但它是 token classification 数据，数据卡关于来源、采集、标注者、敏感信息和用途的内容仍为空；本地 3,821 条 train 中有 3,375 条包含姓名、联系方式、地点、机构或民族等实体。因此它继续限定为 `declared_upstream_provenance_incomplete` / `audit_only`。

结论是当前没有一个已配置的公开中文简历源同时满足“完整 resume_parse 标签、许可和训练用途明确、来源可追溯、隐私可控”。本轮不修改准入配置，也不把 Apache 元数据标签误写成原始简历采集授权。数据获取缺口保持为真实门禁，而不是用下载行数或模板扩写消除。

## 第七轮执行记录（2026-08-12，HISTORICAL）

本轮审查经验硬约束和项目证据。4,797 条 Match 中有 1,996 条 JD 明确要求工作年限，旧标签只有 3 条“满足”；进一步核查发现这 3 条全部来自同一简历中的“25年校招”，被错误解析为 25 年经验。现在仅对 20 以上的两位数招聘届次排除 `校招/社招/春招/秋招` 语境，并保留“2年校招经验”等真实时长。逐 ID 重建只修正 3 条经验标签、3 个分数和 2 个匹配等级。

修复也暴露了不可用的训练分布：1,996 条明确年限要求样本现在全部为“不满足”，train 1,576 / valid 232 / test 188 均没有满足样本。readiness 新增条件分布门禁，要求每个含明确年限要求的 split 同时覆盖满足与不满足；当前 `match.ready_for_sft=false`。所有 2,844 条可训练简历都没有明确经验时长，因此本轮不编造年份平衡数据。

项目证据方面，旧池 2,789 条带 `命中项目` 的样本中有 1,131 条完全没有 JD 技能证据，只因模板出现宽泛岗位方向而命中。项目匹配现在必须包含明确 JD 技能，岗位方向只保留在独立方向评分中。完整重建删除 2,337 条伪项目证据，保留 1,819 条技能证据；1,997 个分数和 269 个匹配等级随之修正。保存的 25 条候选三层重放指标不变，Gold 五类训练重叠仍为 0。

本轮验收：402 个 Python 测试、Ruff、Python 编译、全部 Shell 语法、前端报告冒烟和 `git diff --check` 通过；SFT 主链新鲜。

## 第八轮执行记录（2026-08-12，HISTORICAL）

本轮审查岗位方向污染和 Match 抽样稳定性。旧方向规则把标题中的任意“研究员”直接归为算法工程，导致医药、化学、金融、产业研究等岗位进入技术训练池；同时产品岗会被正文中的“前端、AIGC、数据开发”等协作词带偏。修复只保留标题或正文中的强证据：明确算法/AI/世界模型/安全等技术研究岗继续进入对应方向；“产品岗/产品实习生”按标题归产品经理；食品、药物、生物等领域安全研究不进入网络安全。候选回放还暴露“硬件研发工程师”漏标，现以明确“硬件研发”标题优先归为硬件方向。

全量重建仍为 293,582 条规范化 JD、269,351 条去重 JD；JD 组合池由旧基线 39,765 条降为 38,720 条。过严中间版曾降到 38,640 条，全池复核后补回 71 条安全/AI/模型研究岗和 9 条通过质量筛选的硬件研发岗，不用正文偶然技术词恢复泛研究岗位。最终 JD 质量集仍为 5,300 条，分层为 strict 3,217、strict-plus 270、quality-weak 1,813；50 个 holdout ID 继续排除。

旧 Match JD 选择使用顺序敏感的 `shuffle`。候选池小幅清洗后，1,200 个 JD 只剩 187 个相同，人工 review 队列和逐轮差分几乎失效。现在使用同一 seed 派生的稳定哈希排序，不增加依赖或持久状态；在 38,640 → 38,712 的真实候选池变化上保留 1,193 / 1,200 个 JD（99.4%），只替换 7 个排名边界实体。相同最终输入重建两次的 Match synthetic SHA-256 完全一致。

最终 Match 组合池为 4,796 条（train 3,840 / valid 478 / test 478），包含 1,200 个 JD、2,261 个简历实体；教育弱来源 1,918 条（39.99%），实体跨 split、学历标签矛盾和 Gold 五类训练重合均为 0。1,947 条明确年限要求样本仍全部为“不满足”，所以 `match.ready_for_sft=false`；项目证据为 1,587 条配对、1,734 条明确技能证据。

保存的 25 条候选三层重放仍标记为 `provisional_candidate_diagnosis`：Raw Model 等级 EM 0.56、方向 EM 0.60；Normalized/Product Final 等级 EM 0.92、方向 EM 0.96、命中技能 F1 0.984、缺失技能 F1 0.979、经验 EM 0.92，结构化错例 5 条，解释一致率 1.0。`human_verified_rows=0` 未改变，这些数字不是正式产品准确率。

本轮验收：415 个 Python 测试、Ruff、Python 编译、全部 Shell 语法、前端报告冒烟和 `git diff --check` 通过；SFT 主链新鲜，Match 合成池连续两次重建 SHA-256 一致。DPO 仍按本目标暂停，长期目标保持运行。
